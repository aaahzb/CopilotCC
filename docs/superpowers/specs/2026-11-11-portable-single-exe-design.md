# Windows 绿色单文件桥接设计

日期：2026-11-11
状态：用户已批准设计；不自动提交、推送、打 tag 或发布。

## 目标

Windows 用户只下载、复制和运行一个 `CopilotCC.exe`。它无需安装、管理员权限或注册表写入，可以放在任意普通目录并直接移动。现有双终端、会话恢复、配对和托盘行为保持不变。

这不是安装器，也不在 exe 旁放置 `ccc-terminal.exe`、`pty/` 或 manifest。原生组件集中释放到已有的 `~/.ccc-bridge/runtime/` 数据目录；`CCC_BRIDGE_HOME` 设置的隔离根目录同样生效。

## 为什么需要私有运行目录

当前 Windows 发行包含 GUI 子系统的托盘进程、Console 子系统的终端包装进程和 node-pty 原生 `.node`/DLL。Windows 不能把这些组件全部直接从同一个 GUI exe 的内存中运行。单文件指用户只管理一个便携 exe，不代表运行期间磁盘上不存在任何组件。

运行组件不是用户配置，也不是会话数据。每次启动按内容版本管理，旧版本和不完整临时目录由后续启动回收。

## 交付形态与压缩

构建流程先产生现有完整 Windows 发行目录，再将目录中的全部必要文件打成 ZIP，作为托管资源嵌入一个轻量原生 Windows 启动器。最终公开产物为：

```text
CopilotCC.exe
```

压缩包包含 GUI 主程序、Console 包装、经实探选择的 PTY 运行时和哈希清单，不包含测试假 CLI、验收证据、源码、用户配置或符号文件。目标是达到用户实测的约 40 MB 量级；最终报告必须记录真实字节数，不能在构建前承诺精确大小。

启动器使用 Windows 10 自带的 .NET Framework 与 WinForms，不要求用户另装现代 .NET Runtime。ZIP 通过构建期资源嵌入，不依赖项目路径、网络下载或系统第三方解压软件。

## 启动顺序

启动器依次执行：

1. 显示小型确定性进度窗口，标题和产品名明确为 CopilotCC。
2. 解析配置根目录，并创建 `runtime/` 私有管理目录。
3. 在解压之前扫描并清理 CopilotCC 自己创建的旧版本和临时残留。
4. 校验当前内容版本目录及其文件清单；完整且未被占用时直接复用。
5. 当前版本缺失或不完整时，解压到同一 `runtime/` 下的新临时目录，逐文件校验后原子发布。
6. 启动当前版本的 GUI 主程序；确认进程成功创建后完成启动进度并关闭窗口。
7. 启动失败时保留可见错误，不伪装成功，不启动来源不明的替代程序。

进度按清理、校验、解压和启动阶段更新。复用当前版本时允许快速完成，不为了展示进度而人为延时。

## 目录与版本标识

每个有效负载使用完整内容 SHA-256 作为版本标识：

```text
<configDir>/runtime/<payloadSha256>/...
<configDir>/runtime/.extracting-<payloadSha256>-<random>/...
```

版本目录中只有启动器写入的 `payload-manifest.json` 标记和负载文件。清单记录每个相对路径、大小和 SHA-256。版本标识必须是小写十六进制 SHA-256，不能来自任意目录名或外部参数。

有效当前版本可复用，避免每次启动重复解压。异常中断留下的临时目录不得被当成有效版本。

## 清理与占用边界

每次启动先清理，再校验或解压：

- 删除属于 CopilotCC 且不是当前内容版本的旧版本目录。
- 删除本应用命名的过期解压临时目录。
- 当前版本不完整且确认未被使用时，先清理再重建。
- 正在运行的 CopilotCC 组件所在目录必须保留，不强杀进程、不强删锁定文件。
- 只处理符合专有标记、规范版本名和预期目录层级的条目；拒绝跟随符号链接或 junction。
- 不删除 `config.json`、会话、转录、配对信息、日志或用户放入的其他文件。
- 权限、占用或查询失败时记录并保留该目录，在下一次启动重试；不能把“跳过”报告为已清理。

因此稳态只保留当前版本；若另一个版本仍在运行，可以暂时同时保留它和当前版本。任何清理实现都不能以“保证清洁”为理由破坏活跃进程。

## 重复启动与并发

启动器在清理和发布期间持有 `runtime/` 下的应用级互斥锁，避免两个新启动器同时清理对方正在发布的目录。互斥锁只覆盖准备阶段，不阻止既有托盘正常工作。

若当前或旧版本组件已经运行，清理器通过进程身份与占用检查保留对应目录。具体身份沿用 PID、规范化可执行路径和启动时间，不仅凭 PID 或文件名判断。

解压采用“临时目录完整写入 → 全文件 SHA-256 校验 → 原子改名”的发布方式。目标版本已存在时先复核，不覆盖另一个启动器已经发布成功的目录。

## 路径与负载安全

- ZIP 条目必须是相对路径，使用统一分隔符，不得包含盘符、绝对路径、`..`、空段或反斜杠绕过。
- 拒绝符号链接、重解析点和清单外文件。
- 清单外文件、大小不符或 SHA-256 不符均使该版本无效。
- 启动器只执行已发布且校验通过的固定 GUI 相对路径。
- 启动器不把配对 token、API key、hook token 或进程环境写入进度界面或证据。
- 启动错误只显示阶段和可操作的简短说明，详细诊断不得泄露秘密。

## 对现有运行代码的调整

编译后的 Windows 主程序不能再假定 `ccc-terminal.exe` 和 `pty-manifest.json` 位于自身原始 exe 旁。启动器通过专用环境变量把已校验的负载根目录传给 GUI 主程序：

```text
CCC_PORTABLE_RUNTIME_DIR=<configDir>/runtime/<payloadSha256>
```

`terminalNativeDirectory()` 和 `terminalChildCommand()` 仅在编译态且该变量通过绝对路径、预期目录结构和清单校验时使用此目录。开发态保持现有 `dist/native-dev` 与 tsx 入口，隔离测试可继续注入自己的根目录。

GUI 主进程、终端包装和 Hook helper 必须继承同一负载根目录。禁止静默回退到仓库 `node_modules`、未知旧版本或用户 PATH 中的同名程序。

## 构建与发布

Windows 构建保留内部完整目录作为校验和测试中间产物，但最终 artifact 只包含单文件 exe。发布流程执行：

1. 运行现有 PTY 路线实探与双 exe 编译。
2. 运行原生布局和 SHA-256 校验。
3. 生成完整负载清单并压缩。
4. 编译带图标、无控制台窗口的轻量启动器并嵌入 ZIP。
5. 检查公开产物目录确实只有一个 `CopilotCC.exe`。
6. 从项目树外的空目录运行该单文件，完成隔离冒烟和端到端验收。

现有 macOS `.app`/DMG 构建不在本次改动范围内，不借 Windows 结果宣称 macOS 已验收。GitHub Runner 只有实际触发后才能宣称云端构建通过。

## 测试与真实验收

### 自动测试

- 负载路径、ZIP 条目、清单与版本标识的正反例。
- 清理器只删除自己所有的旧版本与临时目录。
- 活跃版本、未知目录、junction、权限错误和占用错误均被保留。
- 当前版本完整复用、损坏重建、并发发布和中断残留恢复。
- 启动器只选择已校验的 GUI 与 Console 相对路径。
- 生产入口正确使用 `CCC_PORTABLE_RUNTIME_DIR`，变量非法时保守失败。
- 现有桥接与扩展完整测试、类型检查和构建保持通过。

### 真实 Windows 验收

在项目树外已批准的隔离验证根目录中：

1. 空目录只放 `CopilotCC.exe`，不复制任何旁置组件。
2. 记录真实 exe 大小、SHA-256 和进度窗口可见证据。
3. 使用隔离 `CCC_BRIDGE_HOME` 启动，确认先清理后解压，且 exe 旁没有新增文件。
4. 人工植入有标记旧版本、临时残留、未知目录和 junction，验证清理边界。
5. 连续启动、异常中断、损坏当前版本和模拟版本升级，验证不会持续累积。
6. 用真实 Chrome、真实编译负载、真实 Claude Code CLI、ConPTY 和 Windows Terminal 重跑双终端 resume、镜像、退出恢复与清理。
7. 只访问本机假上游，不消耗真实 API；证据不保存请求头或正文。
8. 定向关闭本轮登记的窗口与进程，最终 `remaining=[]`、`errors=[]`。

真实验收必须确认实际运行的是新单文件释放出的同一批负载，不得在项目树内侥幸命中开发资源。
