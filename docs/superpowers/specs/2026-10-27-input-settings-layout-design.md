# CopilotCC 输入区单行与模型、effort 合并设计

日期：2026-10-27

## 已确认的交互方案

采用“底部模型名选 effort”方案。

- 输入框上方的执行选项始终保持一行，只保留“附带网页”、fast 开关、权限模式和模型下拉。
- 删除上方独立的 CC fast 状态文本和 effort 下拉，避免状态与控件把执行选项挤成两行。
- 输入框下方继续显示当前实际模型与 effort。该文本改为按钮，点击后在原位置上方展开 effort 选项。
- CC fast 真值紧跟在模型状态右侧，显示为 `(CC fast on)`、`(CC fast off)`、`(等待 CC 回报)` 或冷却状态。

## 布局与组件边界

改动限定在扩展的 `InputBox.tsx`、`style.css` 和对应测试，不修改 App 的设置回调、WS 协议或桥接。

执行选项行使用禁止换行的 flex 布局。两个保留下拉允许压缩，文本溢出时省略，极窄宽度下也不能生成第二行。

发送行左侧新增一个不可拆散的状态组：模型与 effort 按钮在前，fast 真值在后。状态组内部不换行，并允许压缩省略。effort 弹层相对该状态组向上展开，避免被输入区底边裁掉。

## 模型与 effort 操作

1. 用户仍通过上方模型下拉选择模型，继续调用现有 `onModelChange`，包括自动档。
2. 下方按钮显示现有实际值优先的模型与 effort 文本，并保留“待确认”语义。
3. 点击该按钮打开 effort 选项，再点一次或点击外部关闭。
4. effort 选项包含自动、low、medium、high、xhigh、max。选择后调用现有 `onEffortChange` 并关闭弹层。
5. Escape 关闭弹层。按钮提供展开状态与可访问名称，选项可用键盘聚焦和激活。
6. 弹层只改变扩展本地展开状态，不发送额外设置消息，不影响 busy、草稿、上传和停止操作。

## 真值与异常状态

- 模型、effort 和 fast 的实际值继续使用现有 runtime，不把请求值冒充 CC 真值。
- `effectiveEffort=null` 仍表示 CC 明确未下发 effort，不回退成请求值。
- fast 禁用原因和冷却说明继续通过悬浮提示展示，开关仍只表示用户请求值。
- `settings.error` 保留原有非致命警告区域，不用布局调整掩盖错误。
- 未绑定或断线时的现有禁用行为不变。

## 验证与交付

- 先用失败测试锁定：执行行没有 fast 真值和 effort 下拉，fast 真值位于下方模型状态右侧，CSS 禁止执行行换行。
- 用 DOM 交互测试覆盖：打开 effort、选择并关闭、点击外部关闭、Escape 关闭，以及原模型和 fast 回调不回归。
- 运行扩展完整测试、类型检查、build 和 zip，核对包内外一致性。
- 同步 README 和 TODO。此次没有桥接代码变化，不重建桥接 exe。
- Chrome 真实 UI 的窄侧栏与独立弹窗视觉验收由用户执行，不把自动测试当作视觉验收。

## 非目标

不调整 fast 提升、恢复、冷却或 pending 规则，不修改权限和 effort 的桥接行为，不引入官方登录，不提交、推送或发布。
